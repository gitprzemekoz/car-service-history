# UI theme change to olive — Implementation Plan

## Overview

Switch the app from its dark blue/purple "cosmic" look to a light olive theme based on the shadcn preset `b6thjh1sG`. Take only the preset's colours and Manrope font (keep the `new-york` style and existing components). Then migrate every page and component from hardcoded Tailwind palette classes to shadcn semantic tokens, so the olive palette is actually visible. After that, a future theme change only needs a CSS change.

## Current State Analysis

- `components.json:3,9` has style `new-york` and base colour `neutral`. `src/styles/global.css:6-74` holds neutral oklch tokens, and `@theme inline` at `:75` maps them to Tailwind colours (research.md).
- The only component file that consumes semantic tokens is `src/components/ui/button.tsx`. Its single usage, `src/components/auth/SubmitButton.tsx:18`, overrides it with `bg-purple-600` (research.md).
- The pages use hardcoded classes on the dark `bg-cosmic` gradient (`global.css:113-114`). 19 files are affected, listed per phase below. The same pattern repeats across them:
  - card: `border-white/10 bg-white/10`
  - gradient heading: `from-blue-200 to-purple-200 bg-clip-text text-transparent`
  - text: `text-white`, `text-blue-100/50…/90`
  - links: `text-purple-300`
  - inputs: `border-white/20 bg-white/10 focus:ring-purple-400`
- Status colours: `text-green-300` ("linked") and `text-amber-300` ("waiting") in `dashboard/mechanic.astro:78,80` and `mechanic/clients/[id].astro:70,72`. Red errors appear in `FormField.tsx:53,59` and `ServerError.tsx:11`. `Banner.astro:28-40` has hex info/warning/error variants, and `Layout.astro:20-30` renders only `variant="error"`.
- Other components:
  - `Topbar.astro` is imported only by `Welcome.astro:2`.
  - `Welcome.astro` is imported by `pages/index.astro:2`.
  - `LibBadge.astro` has no importers.
- No tests assert on class names: `src/lib/*.test.ts` covers utils/validation only, and `scripts/smoke.mjs` checks HTTP status and redirects only.
- `.dark` is never applied in `src/`, so the dark token block is inert.

## Desired End State

Every page (landing, signin, signup, confirm-email, client dashboard, mechanic dashboard, client detail) renders on the light olive background, and all of the following use the theme:
- cards use `bg-card` with `border-border`;
- body text is `text-foreground` and secondary text is `text-muted-foreground`;
- primary actions use `bg-primary` (dark olive) and links use `text-primary`;
- inputs use `border-input`, and focus rings use `ring-ring`;
- all text is set in Manrope.

Errors use the `destructive` token. The green and amber status labels keep their hue, darkened for contrast on light backgrounds. No `blue`, `purple`, `indigo`, `pink` or `white` palette class remains in `src/` (apart from shadcn's generated `button.tsx`), and the `bg-cosmic` utility is gone.

### Key Discoveries:

- `npx shadcn@latest apply --preset b6thjh1sG --only theme,font` was verified on a scratch copy with CLI 4.21.0, with no prompts. It changes exactly these files:
  - `components.json`: `baseColor` becomes `olive`, and it adds `rtl`, `menuColor`, `menuAccent`, `registries`;
  - `package.json`: adds `@fontsource-variable/manrope`;
  - `package-lock.json`;
  - `src/styles/global.css`: olive `:root`/`.dark`/chart/sidebar values, `@import "@fontsource-variable/manrope"`, `--font-sans`/`--font-heading` in `@theme inline`, `--radius-2xl..4xl`, and `html { @apply font-sans }`.
- It leaves `button.tsx`, `Layout.astro`, the `new-york` style, `@utility bg-cosmic` and the existing `@layer base` rules untouched.
- In the probe output, `.dark --sidebar-primary` stays blue (`oklch(0.488 0.243 264.376)`). The sidebar is unused and `.dark` is inert, so this has no visible effect.
- Preset `sera` style and `--template astro` are intentionally not used (research.md).

## What We're NOT Doing

- No `sera` style, no `init`, no component reinstall: `components.json` style stays `new-york` and `button.tsx` stays as is.
- No dark mode and no theme toggle. The `.dark` block stays as generated by the preset but is not applied.
- No new status tokens (`--success`/`--warning`/`--info`). Green and amber stay as Tailwind palette classes, only darkened. The Banner warning variant keeps its hex colours.
- No layout, copy, spacing or component-structure changes beyond what the colour swap requires. Decorative elements are recoloured or removed, not redesigned.
- No deletion of the unused `LibBadge.astro`. It is only recoloured, to keep the grep check clean.
- No new visual/regression test tooling.

## Implementation Approach

Use the CLI for the part it does well (tokens and font). Then migrate markup flow by flow with one shared translation table, so every file follows the same mapping and each phase can be checked in the browser on its own.

**Translation table** (the contract for phases 2–3; use judgement for one-offs, but stay within tokens):

| Current (dark cosmic) | Replace with |
| --- | --- |
| `bg-cosmic` page wrapper | `bg-background` (or drop — `body` already has it) |
| `border-white/10 bg-white/10` card/panel | `border-border bg-card text-card-foreground shadow-sm` |
| `border-white/10 bg-white/5` inner card / nav bar | `border-border bg-muted/50` (nav: `bg-card`) |
| gradient heading (`bg-gradient-to-r from-blue-200 … bg-clip-text text-transparent`) | `text-foreground` |
| `text-white`, `text-blue-100/80`, `text-blue-100/90` | `text-foreground` |
| `text-blue-100/50`, `/60`, `/70`, `text-white/40…/80` | `text-muted-foreground` |
| links `text-purple-300 hover:text-purple-100` | `text-primary underline-offset-4 hover:underline` |
| primary button `bg-purple-600 text-white hover:bg-purple-500` | `bg-primary text-primary-foreground hover:bg-primary/90` |
| secondary button `border-white/20 text-white hover:bg-white/10` | `border-border text-foreground hover:bg-accent hover:text-accent-foreground` |
| input `border-white/20 bg-white/10 text-white placeholder-white/40 focus:ring-purple-400` | `border-input bg-background text-foreground placeholder:text-muted-foreground focus:ring-ring` |
| error `border-red-400/60 focus:ring-red-400`, `text-red-300`, `border-red-500/30 bg-red-900/30` | `border-destructive focus:ring-destructive`, `text-destructive`, `border-destructive/30 bg-destructive/10 text-destructive` |
| status `text-green-300` / `text-amber-300` | `text-green-700` / `text-amber-700` |
| accent icons `text-purple-300` | `text-primary` |

## Phase 1: Apply olive tokens and Manrope font

### Overview

Bring the preset's colours and font into the project with the shadcn CLI. After this phase `body` is olive-light with Manrope, but the pages still show the dark cosmic wrapper until phases 2–3.

### Changes Required:

#### 1. Run the preset apply

**File**: `components.json`, `package.json`, `package-lock.json`, `src/styles/global.css`

**Intent**: Run `npx shadcn@latest apply --preset b6thjh1sG --only theme,font` from the repo root, then review the diff against the expected set in Key Discoveries. Keep `@utility bg-cosmic` for now, because phases 2–3 still reference it.

**Contract**: `components.json` keeps `"style": "new-york"` and ends with `"baseColor": "olive"`. `global.css` keeps the same `@theme inline` colour mappings plus `--font-sans: 'Manrope Variable', sans-serif`. `@fontsource-variable/manrope` is in `dependencies`. The diff touches only these four files; any other file in the diff is reverted. Restore the trailing newline in `global.css` if the CLI drops it (observed in the probe); the pre-commit `prettier --write` on `*.css` also handles it.

### Success Criteria:

#### Automated Verification:

- `git diff --name-only` lists exactly `components.json`, `package.json`, `package-lock.json`, `src/styles/global.css`
- `grep -n '"style": "new-york"' components.json` and `grep -n '"baseColor": "olive"' components.json` both match
- Lint passes: `npm run lint`
- Unit tests pass: `npm test`
- Production build succeeds: `npm run build`

#### Manual Verification:

- `npm run dev`: text on every page renders in Manrope (check DevTools computed `font-family`)
- The default shadcn button variants are unaffected except for colour. Pages still render (the cosmic look is expected until phase 3).

## Phase 2: Migrate the auth flow

### Overview

Move the signin, signup and confirm-email screens and their React components onto semantic tokens, including the error styling and the global error Banner.

### Changes Required:

#### 1. Auth pages

**File**: `src/pages/auth/signin.astro`, `src/pages/auth/signup.astro`, `src/pages/auth/confirm-email.astro`

**Intent**: Replace the `bg-cosmic` wrapper, the white-glass card, the gradient heading, the muted blue text and the purple links using the translation table.

**Contract**: No `bg-cosmic`, `white`, `blue`, `purple` palette classes remain in these files. Markup structure is unchanged.

#### 2. Auth components

**File**: `src/components/auth/FormField.tsx`, `ServerError.tsx`, `SubmitButton.tsx`, `PasswordToggle.tsx`, `SignUpForm.tsx`

**Intent**:
- `FormField`: label becomes muted/foreground, and the input follows the table's input row; the error state uses `destructive`.
- `ServerError`: becomes a destructive alert.
- `SubmitButton`: drop the purple colour override so the shadcn `Button` default (primary) variant shows. Keep only layout classes such as `w-full`. The spinner uses `primary-foreground` borders.
- `PasswordToggle`: the icon becomes `text-muted-foreground hover:text-foreground`.
- `SignUpForm.tsx:59`: the hint text becomes muted.

**Contract**: The `SubmitButton` props and behaviour are unchanged, and it still renders `<Button type="submit" disabled={pending}>`. Validation and error rendering logic are untouched; only `className` strings change.

#### 3. Banner

**File**: `src/components/Banner.astro`

**Intent**: In the scoped `<style>`, make the `error` variant use `var(--destructive)` (border/text, with a light tinted background, e.g. `color-mix(in oklch, var(--destructive) 10%, transparent)`). Make the `info` variant use `var(--secondary)` / `var(--secondary-foreground)` / `var(--border)` instead of blue hex. The `warning` variant keeps its amber hex values.

**Contract**: The `variant` prop API (`info | warning | error`) is unchanged, and `Layout.astro` needs no edit.

### Success Criteria:

#### Automated Verification:

- `grep -nE '(bg-cosmic|(bg|text|border|ring|from|via|to|placeholder)-(white|blue|purple|indigo|pink))' src/pages/auth src/components/auth` returns nothing
- `grep -nE '#(dbeafe|1e3a8a|3b82f6|fee2e2|7f1d1d|dc2626)' src/components/Banner.astro` returns nothing
- Lint passes: `npm run lint`
- Unit tests pass: `npm test`
- Production build succeeds: `npm run build`

#### Manual Verification:

- `/auth/signin` and `/auth/signup` render as a white card on the light olive background. The heading is dark olive, links are olive (primary) and the submit button is dark olive with light text.
- Submit with invalid data: the field error border and message and the server error alert are red (destructive) and readable.
- The pending state shows the spinner visible on the button.
- `/auth/confirm-email` matches the same look.
- Temporarily unset a Supabase env var so `Layout.astro` shows the error Banner, and confirm it uses the destructive colour.

**Implementation Note**: After completing this phase and all automated verification passes, pause here for manual confirmation from the human that the manual testing was successful before proceeding to the next phase.

## Phase 3: Migrate the landing page and dashboards, remove `bg-cosmic`

### Overview

Apply the same translation to the landing page, the client and mechanic dashboards and the shared components. Then remove the now-unused cosmic utility, so the whole `src/` tree is free of hardcoded theme colours.

### Changes Required:

#### 1. Landing page

**File**: `src/components/Welcome.astro`, `src/components/Topbar.astro`

**Intent**: Migrate using the table.
- Welcome's primary CTA becomes `bg-primary`; the secondary CTA follows the table's secondary row; feature cards become `bg-card`; icons become `text-primary`.
- Welcome's decorative blurred orbs (purple/blue/indigo at `Welcome.astro:7-9`) are recoloured to low-opacity `bg-primary/5…/10`, or removed if they muddy the light background.
- Topbar gets a `bg-card border-border` bar with `text-muted-foreground` secondary text and `text-primary` links.

**Contract**: Structure, copy and links are unchanged.

#### 2. Dashboards

**File**: `src/pages/dashboard.astro`, `src/pages/dashboard/mechanic.astro`, `src/pages/dashboard/mechanic/clients/[id].astro`

**Intent**: Replace the wrapper, cards, gradient headings, text, links and the sign-out button using the table. The status labels become `text-green-700` / `text-amber-700`.

**Contract**: No data or auth logic changes; only `class` attributes change.

#### 3. Shared dashboard components

**File**: `src/components/ServiceHistory.astro`, `src/components/mechanic/AddServiceEntryForm.tsx`, `src/components/ui/LibBadge.astro`

**Intent**:
- `ServiceHistory`: entry cards become `bg-muted/50 border-border`; labels become muted and values foreground.
- `AddServiceEntryForm`: the label at `:119` and the input at `:130` follow the table.
- `LibBadge`: becomes `bg-secondary text-secondary-foreground`, with the version pill `bg-primary/10 text-primary`.

**Contract**: Component props are unchanged.

#### 4. Remove the cosmic utility

**File**: `src/styles/global.css`

**Intent**: Delete `@utility bg-cosmic`, since nothing references it any more.

**Contract**: The rest of `global.css` (preset tokens, `@theme inline`, `@layer base`) is untouched.

## Testing Strategy

### Unit Tests:

- None added. The change is presentational only (class strings and CSS tokens). The existing `src/lib/*.test.ts` must stay green.

### Integration Tests:

- `npm run smoke` (HTTP-level auth flow) guards against the migration accidentally breaking a page render or a form post.

### Manual Testing Steps:

1. `npm run dev`, then visit `/`, `/auth/signin`, `/auth/signup`, `/auth/confirm-email`.
2. Sign in as a client: check `/dashboard`.
3. Sign in as a mechanic: check `/dashboard/mechanic` and a client detail page (both status labels, service history, the add-entry form).
4. Trigger form validation errors and a server error (wrong password).
5. Confirm there is no dark gradient, no purple/blue accent, and no unreadable text anywhere.

## Performance Considerations

- Manrope is added as a variable woff2 via Fontsource and bundled by Vite. It is one font file per subset, which is acceptable. No other runtime impact.

## Migration Notes

- Rollback is a revert of the change commits. There is no data or config migration.
